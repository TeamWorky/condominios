# Implementation Plan: Payments Backend CRUD

**Branch**: `006-payments-backend` | **Date**: 2026-05-20 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/006-payments-backend/spec.md`

## Summary

Implement a complete Payments CRUD backend module following the established Residents module pattern. The module provides 7 REST endpoints for creating, listing (by condominium and unit), viewing, updating, changing status, and soft-deleting payments. All data is scoped by condominiumId from JWT. Status transitions are enforced via a static transition map with PAID and CANCELLED as terminal states.

## Technical Context

**Language/Version**: TypeScript 5.9, Node.js 24.x
**Primary Dependencies**: NestJS 11, TypeORM 0.3.x, PostgreSQL, Redis
**Storage**: PostgreSQL (TypeORM), Redis (cache)
**Testing**: Jest 30, ts-jest, Supertest
**Target Platform**: Linux server (Node.js runtime)
**Project Type**: Backend API (RESTful)
**Performance Goals**: <500ms p95 response time for list queries with up to 500 payments
**Constraints**: Rate limiting 100 req/min (global), JWT auth required, multi-tenant scoping
**Scale/Scope**: Condominiums with up to ~500 units and ~5000 payments per condominium

## Key Implementation Details

### Status Transition Map

```typescript
const VALID_TRANSITIONS: Record<PaymentStatus, PaymentStatus[]> = {
  [PaymentStatus.PENDING]: [PaymentStatus.PAID, PaymentStatus.OVERDUE, PaymentStatus.PARTIAL, PaymentStatus.CANCELLED],
  [PaymentStatus.OVERDUE]: [PaymentStatus.PAID, PaymentStatus.PARTIAL, PaymentStatus.CANCELLED],
  [PaymentStatus.PARTIAL]: [PaymentStatus.PAID, PaymentStatus.CANCELLED],
  [PaymentStatus.PAID]: [],
  [PaymentStatus.CANCELLED]: [],
};
```

### Condominium Scoping (QueryBuilder pattern)

```typescript
// Scope payments by condominiumId through unit → building → condominium chain
queryBuilder
  .innerJoin('payment.unit', 'unit')
  .innerJoin('unit.building', 'building')
  .innerJoin('building.condominium', 'condominium')
  .where('condominium.id = :condominiumId', { condominiumId });
```

### Cache Strategy

| Key Pattern | TTL | Invalidation |
|-------------|-----|-------------|
| `payments:condo:{condoId}:*` | SHORT (300s) | On create/update/delete/status-change |
| `payments:unit:{unitId}:*` | SHORT (300s) | On create/update/delete/status-change |
| `payments:{id}` | MEDIUM (1800s) | On update/delete/status-change |

### Protected Operations

| Operation | Condition | Error |
|-----------|-----------|-------|
| Update amount | Status is PAID | "Cannot update amount of a paid payment" |
| Soft delete | Status is PAID | "Cannot delete a paid payment" |
| Status change | Invalid transition | "Invalid status transition from {from} to {to}" |
