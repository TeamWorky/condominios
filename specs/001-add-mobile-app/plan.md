# Implementation Plan: Mobile App - React Native

**Branch**: `001-add-mobile-app` | **Date**: 2026-03-19 | **Spec**: [spec.md](spec.md)

---

## Summary

Add an Expo-managed React Native mobile app (`apps/mobile`) to the existing Nx monorepo. The app shares types from `libs/shared`, connects to the NestJS backend at `localhost:3000`, and is fully integrated into the `npm run start:dev` orchestrator. The initial scope is a minimal login shell — feature parity with the web app is out of scope.

---

## Technical Context

**Language/Version**: TypeScript 5.9, Node.js 24.x
**Mobile Framework**: Expo SDK 53 (React Native 0.79)
**Nx Plugin**: `@nx/expo@22.5.4` (matches installed `nx` version)
**Metro**: 0.81+ (bundled with Expo SDK 53)
**Shared Types**: `@condominios/shared` via `libs/shared/src`
**API**: NestJS at `http://localhost:3000/api/v1`
**Platform targets**: iOS simulator, Android emulator, web browser, physical device via Expo Go
**Constraints**: No new backend endpoints. No feature parity with web. npm only (no yarn/pnpm).

## Implementation Phases

### Phase 1 — Nx + Expo Scaffold

1. Install `@nx/expo@22.5.4` as dev dependency.
2. Generate `apps/mobile` with `nx g @nx/expo:app mobile --directory=apps/mobile --e2eTestRunner=none`.
3. Manually bump Expo SDK to `~53.0.0` in `apps/mobile/package.json`.
4. Run `npm install` from monorepo root.
5. Register `@nx/expo/plugin` in `nx.json`.

### Phase 2 — Path Alias and Metro Configuration

1. Replace generated `apps/mobile/metro.config.js` with monorepo-aware config (`watchFolders`, `extraNodeModules`, `nodeModulesPaths`).
2. Create `apps/mobile/babel.config.js` with `babel-preset-expo` + `babel-plugin-module-resolver` (`@condominios/shared` alias).
3. Install `babel-plugin-module-resolver` as devDependency in `apps/mobile/package.json`.
4. Replace generated `apps/mobile/tsconfig.json` — extend `expo/tsconfig.base`, add `paths` block with `baseUrl: "../.."`.
5. Verify: import a type from `@condominios/shared` in `apps/mobile/src/app/index.tsx` and confirm `npx tsc --noEmit` passes.

### Phase 3 — Orchestrator Integration

1. Add `8081` to `PORTS_TO_CLEAR` in `start-all.js`.
2. Add the mobile task to the `tasks` array:
   ```js
   { name: 'mobile', cmd: 'npm', args: ['run', 'start:mobile'] }
   ```
3. Add scripts to root `package.json`:
   ```json
   "start:mobile": "nx start mobile",
   "start:mobile:ios": "nx run-ios mobile",
   "start:mobile:android": "nx run-android mobile"
   ```
4. Verify: `npm run start:dev` shows `[mobile]` prefix in terminal output.

### Phase 4 — Minimal Login Shell

1. Create `apps/mobile/src/config/api.config.ts` with `EXPO_PUBLIC_API_URL`.
2. Create `apps/mobile/src/services/http.client.ts` — Axios instance with base URL and JWT interceptor.
3. Create `apps/mobile/src/services/auth.service.ts` — `login()`, `logout()`, `refresh()` calling the existing API.
4. Implement login screen (`apps/mobile/src/app/(auth)/login.tsx`) using React Native + basic styling.
5. Create `.env.example` documenting `EXPO_PUBLIC_API_URL` for iOS, Android emulator, and physical device.

### Phase 5 — Documentation

1. Update `README.md` — add **Mobile App** section with:
   - Prerequisites (Expo CLI, simulators, Expo Go)
   - All `start:mobile*` commands
   - Environment variable configuration (`EXPO_PUBLIC_API_URL`)
   - Android-specific note (`10.0.2.2`)
2. Update `CLAUDE.md` if architecture or workflow rules change.
